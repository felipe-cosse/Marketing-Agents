# ORCH-09 verification note

Validated read-only Runs now persist one bounded execution snapshot containing the plan, selected instances, routing assignments, ordered RunSteps, dependencies, and exact sequence-one step histories. A domain-owned hash projection is shared with RUN-02, so activation, readiness, completion, and replay recompute the exact structural plan hash from persisted step fields. Plan creation changes the parent Run and appends plan and step audit witnesses in the same outer transaction. Replay preserves the existing audit event and actor context instead of rewriting them with the new caller; a partial plan, missing initial history, structural-field mutation, conflicting replay, or post-flush fault fails closed without backfilling evidence. Identical structural plan hashes remain correctly scoped to distinct Runs.

Accepted Run and RunStep transitions now append typed audit events in the same unit of work as their state and transition rows. A failed single-event append rolls back ordinary Run and Step mutations. Run completion derives its counts from the persisted steps, and MARK_READY reconstructs the complete persisted graph before evaluating dependency success, so caller-supplied counts and a deleted dependency row cannot authorize progress. Generic WRITE readiness and execution remain unavailable: write-bearing plan persistence fails before mutation until RUN-08 and ORCH-08 can compose the complete authorization-set and approval epoch atomically.

Audit metadata uses event-specific allowlists, bounded canonical JSON, classification-aware redaction, hydration-time revalidation, and integrity fingerprints. Actor and correlation identifiers are server-issued pseudonyms, while accepted lifecycle mutations and rejected Run attempts have distinct typed shapes. These typed context factories do not authenticate a caller: API and worker composition must derive them from authenticated server-owned principals, never request-body or actor-header values. Rejected attempts carry their own stable identity and observed snapshot without consuming a mutation version; an exact attempt replay does not allocate another sequence, while changed semantics under the same identity conflicts.

The audit repository allocates a contiguous `run_sequence` with a transactional per-Run counter. Independent step transactions on one Run prove two successful concurrent allocations, and missing first or tail rows make reads and later appends fail closed without healing or counter drift. This is deliberately a per-Run cursor claim only: `global_sequence` is an internal row identity and is not a cross-transaction commit-order cursor. API-07 must introduce its own transactional global cursor or fixed-snapshot protocol before exposing a lossless global feed.

File-backed SQLite tests cover restart pagination, cross-context replay, plan and ordinary mutation rollback, plan and sequence races, missing graph/history/audit rows, direct structural-step tampering, forged completion counts, rejection identity, and two Runs sharing one structural plan hash. Domain and security suites cover the exact effect-aware lifecycle, post-issuance mutation, impossible event hydration, secret/PII canaries, and append-only repository surface. Machine authority: `ORCH-09.json`. RUN-06 retains complete action, attempt, receipt, output, artifact, and safe-error timeline integration; SAFE-07 retains retention-time pseudonymization; DEL-04 retains migrations; ORCH-06 retains worker policy; and the database remains a trusted residual boundary for the ORCH-04 routing hash because the full trigger and slot-policy projection is not persisted here.
