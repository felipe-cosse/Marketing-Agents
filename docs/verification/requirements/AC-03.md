# AC-03 exact department deployment distribution

Requirement: department instance counts are 12/6/5/14/6, respectively Social
media, Blog and SEO, Email, Community, and Partnerships.

Status: implemented and locally exercised. The final committed feature must
pass the declared gates and retain its tree-bound attestation before merge.

## Independent count derivations

The acceptance journey uses default `create_app(Settings(...))` catalog
composition and real ASGI routes. No static query result is injected.

For the entire 43-instance inventory it independently counts the flat
instance-to-template-to-department join and the nested hierarchy, then compares
both with each endpoint's advertised five-department summary. It verifies unique
instance IDs, equal inventory sets, and each individual instance's actual parent
department. Merely returning the expected aggregate numbers cannot hide swapped
instance assignments or duplicate summary entries. Actual department and template
identities are checked for uniqueness before dictionary conversion, so empty
duplicate departments cannot disappear behind the count calculation. Root and orchestrator control-
plane identities are excluded from the deployment inventory.

A private source copy disables one deployment per department. Both API views
must retain those exact five disabled identities in the same structural counts.
This is a source-default test, not a claim about live database configuration edits.

## Negative controls

The compiler test moves one one-instance Social media template to a valid Blog
function in a copied source catalog. A deliberately weak global-count-only
contract proves that the mutation is structurally coherent at 5/12/36/43 and has
distribution 11/7/5/14/6. That weak contract is only fixture qualification: the
actual acceptance assertion requires the default v1 compiler to reject the
mutation with `contract-distribution`, not a global `contract-count` error.

A separate control changes only the release lock's distribution, preserving its
semantic hash, global counts and total of 43. Production release verification
must reject that lock. Neither control changes tracked catalog files or weakens
the application's default contract.
