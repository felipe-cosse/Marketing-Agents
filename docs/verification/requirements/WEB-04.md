# WEB-04 verification

WEB-04 adds a schema-generated manual dry-run workflow to the selected-agent inspector. The form compiles the already cross-bound `inputSchema` from the strict detail response; it does not issue another schema request. The compiler accepts only closed, bounded objects and nested objects, required fields, strings, numbers, integers, booleans, enums, bounded arrays, defaults, examples, supported bounds and formats, canonical `x-sensitive`, and allowlisted presentation-only `x-ui`. Unsafe property names, open objects, references, composition, conditionals, unbounded strings or arrays, unsupported annotations, excessive depth, and excessive field counts produce a stable unsupported-schema state instead of speculative controls.

Defaults come only from declared `default` annotations. Draft numbers remain editable strings until client validation produces finite JSON numbers. Optional blank controls are omitted, calendar dates and date-times are checked, patterns and bounds produce pointer-addressed static messages, and no validation message reflects a submitted value. The dependency-free witness compiles all 36 real catalog input schemas through the production compiler and checks the full synthetic subset, defaults, numeric normalization, format failure, sensitive-message redaction, safe pointer mapping, and fail-closed rejection.

The mutation boundary sends exactly `{ input, executionMode }` to `POST /api/v1/agent-instances/{instance_id}/dry-runs` with same-origin credentials, no-store caching, JSON media types, the private session CSRF header, and one printable memory-only idempotency key. The existing configuration session boundary now delegates to the same private token cache. A `403 csrf_token_invalid` refreshes the session once and replays the identical serialized body and key; no other failure retries automatically. A strict `202` receipt must cross-bind the selected instance, submitted mode, event/work/run IDs, and resource URLs. Strict Problem Details map only safe `/input/...` pointers to rendered fields and otherwise remain a request-level failure.

The panel appears only for a session containing `operator`, an enabled deployment, a template supporting manual input, and no explicitly disabled manual binding. An absent binding remains available, matching the API resolver. `Run with mocks` appears only when connector mode is `mock`; `Create dry run` remains the default. Mutating templates explain that each external action still requires its configured approval and that admission itself never approves or dispatches an action. Sensitive fields use appropriate controls, disable browser assistance where applicable, stay in React memory, and clear after acceptance.

Client errors focus a summary whose controls move focus to the corresponding invalid field. Server field errors use the same deterministic IDs and static safe copy. Network, validation, conflict, and service failures preserve the draft and exact retry key. `Stop waiting` aborts only the browser request, explicitly says the server may already have accepted it, retains the retry key, and revalidates authoritative detail and status queries. A successful response announces `Dry run accepted`, clears the draft and retry key, invalidates selected detail and status, links to the authoritative run resource, and never claims execution, publication, delivery, or completion.
