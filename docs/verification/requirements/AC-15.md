# AC-15 — Full-suite external-network isolation

Requirement: `No test performs external network call.`

Status: implementation and focused controls; the four complete, exact-commit
offline suites below must pass before this requirement is merged as verified.

## Boundaries

Python's root conftest installs the guard before test collection. Transport and
forward/reverse DNS entry points reject external destinations before delegation.
Localhost is converted to a numeric loopback address before native calls, and
numeric-only resolution flags prevent an accidental OS resolver lookup. Local
Unix sockets and numeric loopback remain available to owned local test stacks.
Denied operations use categorical errors without hostnames, URLs or credentials.

Caught denials remain in a monotonic ledger. Test lifecycle and session-final
checks fail otherwise-passing tests, including collection and higher-scope fixture
attempts. Deliberate negative controls must acknowledge exactly one actual guard
denial; a no-op, a different error, nested acknowledgement or a swallowed error
cannot satisfy that control. The guard is reapplied around pytest fixture setup
to coexist with the stricter pytest-socket policy.

The existing Node guard blocks TCP, HTTP(S), TLS, UDP, DNS and fetch; Vitest
teardown checks its denial ledger. Tests use explicit in-memory transports;
MSW is not installed and is not presented as the network boundary.
The complete Vitest inventory retains one isolated thread worker; it does not
filter tests or share file environments. The real nested denial canary inherits
the same configuration. Ruff's Rayon worker count remains fixed at one inside
the acquired image and validated execution environment. These pinned execution
settings retain every formatting/lint stage and file selection; they are not
exceptions to the kernel observer's classification rules.

The backend's complete pytest inventory uses pinned pytest-xdist with exactly two
local workers, file-level distribution and no worker restart. No test-name filter
or assertion timeout is added. Controller-only diagnostics count all reports once
and retain a bounded multiset of active source-declared tests, without parameter
IDs. Worker lifecycle-denial evidence must also reach the controller; parallel
execution cannot turn a caught collection/session denial into success.
Public pytest hook monitoring finalizes worker counts only after every
session-finish wrapper has unwound. The controller checks bounded, atomic,
nonce-bound proofs in its own private temporary directory after worker shutdown;
an early worker-finished message is insufficient. Missing, malformed, duplicate,
incomplete or stale final evidence fails the run. These proofs require local
workers, contain no destinations or payloads, and are removed after validation.

Playwright guards pin the exact loopback origin, including its scheme and port.
The shared fixture now guards the default and future browser contexts, test
request fixture, context/page request clients and request-context factory.
Direct `browser.newPage`, proxy/service-worker opt-ins, route removal and HAR
replacement fail closed. API requests and route forwarding force zero redirects;
caller-supplied redirect counts or URL overrides cannot bypass validation. Each
context retains its guard for its lifetime, and teardown checks caught attempts.
OBJ-06 retains its native browser transport so real mutation requests still have
browser-generated Fetch Metadata. DEL-05's read-only smoke uses safe forwarding.
The ordinary Playwright harness requests graceful SIGTERM shutdown of its owned
API and preview servers, with a ten-second force-kill fallback. Startup deadlines,
test assertions and the complete browser inventory are unchanged.

## Prebuilt full-suite execution

Run these from the pinned local toolchain and a clean committed checkout:

```sh
make acquire-offline-tests
make verify-offline-tests
```

Acquisition is explicitly network-enabled for pinned base images and frozen
Python/Node/Chromium dependencies. It exports only Git-tracked source, validates
the export against Git objects, and builds the combined Python 3.12 / Node 24
verification image. No host credentials, local state or dependency directories
are copied. Acquisition installs the project after copying its source, so native
children can import it without relying on inherited `PYTHONPATH`. Runtime test
execution is a separate command and never builds, pulls or installs anything.

Verification selects exactly one existing immutable image for the current clean
HEAD, tree and export fingerprint; zero or ambiguous matches fail. An explicit
`AC15_IMAGE=sha256:...` may select the same verified identity. Each suite gets two
fresh, owned containers from that image. Both use `--network none`, private
PID/cgroup/IPC namespaces, Docker init, no host mounts or published ports,
no new privileges and the default Docker seccomp profile. The test target runs
as UID/GID 10001 with all capabilities dropped. Its container layer remains
writable for the existing cache/build behavior, subject to source-drift checks.
Only the separate collector runs as root with exactly `BPF` and `PERFMON`
capabilities; its root filesystem is read-only. Neither role uses privileged
mode, host namespaces or `SYS_ADMIN`. Inspection precedes execution.
Inside the target, loopback must be the only active
interface, IPv4 must have no routes, and IPv6 routes may target only loopback.
Kernel-created dormant tunnel devices are allowed only when their administrative
flags and operational state both show they are down; the container cannot gain
the capabilities needed to activate them. Non-interface sysfs control files are
not mistaken for network devices. Unguarded Python and Node child canaries must
receive `ENETUNREACH` for the reserved TEST-NET address before any suite runs.
These deliberate kernel controls are separate from normal test traffic.

The browser suite additionally uses an explicit IP-datagram-disabled test
profile. Pinned Chromium performs an IPv6 reachability probe even for native
loopback requests; its [resolver implementation](https://github.com/chromium/chromium/blob/151.0.7922.34/net/dns/host_resolver_manager.cc)
attempts a connection to a public address. The profile prevents IPv4/IPv6
datagram socket creation, before any destination-bearing call, rather than
exempting that address or hiding `connect`/`send` from the auditor. Docker's
existing restrictions remain in force. Installation requires the supported
architecture, a single thread and no inherited socket descriptors. Child and
grandchild controls prove the denial, while real local TCP, Unix and Netlink
controls prove the transports needed by the browser remain available.
The existing external-TCP and masking-filter controls then run under the same
profile. Backend, frontend and native suites do not install this extra policy.

### Native target and observer qualification

The production observer is scoped to Linux native ARM64, little-endian 64-bit
processes. Before observer attachment, the trusted single-threaded target installs
a fixed audit-architecture guard layered on Docker's policy. It permits native
syscalls without masking their numbers and kills foreign-ABI syscalls. Two
source-generated, static exit-only ELF probes provide a native exit-42 positive
control and an ARM EABI5 negative control. `ENOEXEC` or `SIGSYS` establishes
foreign execution rejection; no absence of `CONFIG_COMPAT` is inferred. An exit
of 42 alone never qualifies foreign execution. Probe files and working
directories are owned temporary storage, with an empty child environment and a
zero ordinary core-file limit; this is not a claim about host piped core handlers.

Docker may translate the foreign ELF through a native QEMU interpreter. Under
the user's explicit approval, this has a separate `native_emulation` proof:
a fixed source-owned ARM32 guest signals readiness, blocks on a private pipe,
then exits 42 only after the fixed release byte. While held, its actual executable
must have an ELF64 little-endian AArch64 header, with unchanged executable metadata,
process start identity, private namespaces and cgroup. Every bounded emulator
thread must retain UID 10001, zero capabilities, no new privileges and seccomp.
The header hash proves header consistency, not whole-binary provenance. The
two-second probe budget includes independent kill/reap cleanup, and the trusted
parent's ordinary two-process baseline must be restored afterward.

After observer attachment, one additional fixed ARM32 guest repeats the same
native-host handshake, makes a real TEST-NET connection that must receive
`ENETUNREACH`, and connects successfully to an owned Unix listener. Exactly one
external attempt, one Unix attempt and one rejection must reach the unchanged
collector; any unknown, control mutation, read error or additional rejection
still fails. Host and target bind this conditional phase to the source inventory
and the initial native-executable header proof. No Docker settings are changed.

This proof covers actual native host kernel calls, including QEMU translations;
it does not claim to audit emulated guest operations handled wholly in QEMU
userspace. For example, [QEMU's translation loop](https://github.com/qemu/qemu/blob/v10.0.0/linux-user/syscall.c)
may stop translating a guest `sendmmsg` vector after an early error. Every element
presented to the native kernel's `sendmmsg` remains
audited under the existing rule. The fixed architecture guard still rejects
actual foreign kernel ABI calls; no observed native attempt receives an exemption.

Qualification rejects inherited socket and io_uring descriptors and requires a
real `io_uring_setup` call with valid empty parameters to fail with `EPERM` or
`ENOSYS`. The private cgroup root must be read-only with no subgroups. Successful
verification keeps its trusted parent alive until both hooks detach, preserving
the cgroup identity.
Before every phase snapshot and final detach, the PID namespace must return to
exactly that parent and Docker init, each with one native thread and unchanged
start time, namespace and cgroup identity. At most one second is allowed for
native task shutdown; reparented children, zombies or other leftovers fail.

A source-bound eBPF entry hook on native `do_el0_svc` classifies `connect`,
`sendto`, `sendmsg`, `sendmmsg`, `prctl` and `seccomp` before ptrace/seccomp handling.
Its [ARM64 entry semantics](https://github.com/torvalds/linux/blob/v7.0/arch/arm64/kernel/syscall.c)
are checked against live BTF function/register layout. Global hook attachment
filters the exact target cgroup before any register or user-memory inspection;
the separate collector's own connected controls must contribute zero counts.
Unsupported attachment, architecture, capability or BTF layouts fail; there is
no alternate observer or unaudited fallback.

The observer uses the native low-32-bit syscall and integer argument semantics,
preserving 64-bit pointers. Every slot of a valid 1–1,024-element `sendmmsg`
vector is classified, even after an earlier bad destination or header. Only
numeric loopback, Unix transport, local kernel IPC and structurally connected
sends pass; external, unknown, unreadable or invalid-vector evidence fails.
Every filter-installation attempt and unknown control operation is rejected.
Only the fixed observation-neutral `prctl`/`seccomp` allowlist passes. Output-only
`SECCOMP_GET_NOTIF_SIZES` queries use a paired exit hook: successful return and
six readable output bytes are required, rather than guessing output at entry.
The bounded 4,096-entry pending map rejects stale/duplicate state; snapshots must
have no pending entries and equal started/completed output-query counts.

The host matches each phase to the complete source-declared command inventory.
Trusted profile setup precedes attachment; connected negative controls have exact
expected counts, and ordinary suite phases allow no rejected attempts. A child
that catches its TEST-NET error still contributes an external attempt. A real
Unix-socket positive control and external grandchild prove connected observation
and descendant scope. A masking-filter child must expose both its filter install
and its seccomp-denied `connect`, even though it catches `EPERM`. These controls
run only after the isolated namespace is proved. Browser TCP/Unix/Netlink controls
remain under the browser-specific profile described above.

Reports bind source/image identity, live BTF hash, exact bytecode hashes,
program/map identities, validated link targets, verifier evidence, ordered snapshots and categorical
counters. Missing output, nonempty pending state, counter regression/overflow,
failed conservation or either hook's recursion misses are fatal. Counters are
never reset, so errors cannot disappear between phases. Entry attaches after exit;
final cleanup detaches entry first, then exit, after target quiescence. No payload,
destination address, process name or raw application output is retained.

The previous strict strace parser and byte/file parity tests remain regression
fixtures only. Their unknown-record rules and bounded streaming reader are not
relaxed, but production verification neither invokes nor falls back to ptrace.

For an individual full suite, use e.g.
`make verify-offline-tests AC15_SUITE=backend`. Selection does not add test-name
filters. The evidence manifest declares all four suites separately; passing one
does not establish AC-15.

Source hashes, modes and execution-input inventory are checked before and after
commands; only explicitly generated/cache/dependency locations are excluded
from the added-file check. Reports are
written outside the repository and bind the commit, tree, lock hashes, export
fingerprint, immutable image, container boundary and fixed command inventory.
Only bounded diagnostics and output hashes are retained in reports, not raw
application logs or environment values. An audit failure retains completed command
evidence and identifies the failing fixed suite command without exposing raw
output. Backend audit failures and timeouts also retain the existing
bounded, source-allowlisted stage/test projection; partial timeout output is
explicitly distinguished from a completed child's output. A rejected phase may
drain its source-bound failure report for at most two seconds within the remaining
host deadline; the original rejection remains authoritative. Cleanup addresses only
containers with this invocation's exact owner label and immutable image identity. Images remain
available for repeat verification; unrelated Docker resources are untouched.

Preflight consumes the existing 1,700-second shared suite budget. A separate
1,720-second whole-container alarm also bounds observation and final source checks;
the 1,740-second host alarm leaves a shared 30-second owned-cleanup budget and
reporting time before the unchanged 1,800-second manifest gate. Both roles share
that cleanup deadline, with independent container removal, attached-client reaping
and pipe closure. The target is removed only after the collector is confirmed
stopped or absent. If collector cessation cannot be confirmed, cleanup fails and
reports the retained target; its failure hold ignores protocol EOF but still ends
at the original 1,720-second limit. This is not an indefinite cgroup-lifetime
guarantee after a daemon/control failure. Neither individual test deadlines nor
the manifest ceiling are extended.

## Connected negative controls

Python transport tests install harmless delegates underneath the guard, so even
a broken guard cannot perform real external DNS or socket operations. Child
pytest controls prove that caught collection, fixture and test-body denials make
the session fail without exposing the synthetic private hostname.

Actual Chromium controls use owned loopback tripwire servers, never external
hosts. Nineteen otherwise-passing caught violations must each fail only automatic
teardown, with zero tripwire hits. Two allowed-origin/in-memory controls pass,
and reused contexts fail separately. The six existing OBJ-06 native transport
controls remain mandatory through the real runtime browser harness.
The reused native child guard exercises all five socket/DNS denial boundaries
without allocating an IP datagram socket: its existing AF_INET stream descriptor
also invokes the guarded `sendto` method. This proves destination denial before
delegation, not UDP delivery. Isolated-child regressions forbid datagram
allocation and prove that each individually broken guard reaches its safe
underlying tripwire, never an operating-system network delegate.

The focused manifest gate now includes the native boundary, bytecode, collector
and protocol controls. They exercise safe synthetic/fake kernel inputs and
failure paths without installing a host filter or attaching a host observer.
Earlier focused and standalone prototype results are not substitutes for the
four complete exact-commit kernel-isolated suites using the integrated observer.

## Limits and merge protocol

The host monkeypatch guards do not sandbox arbitrary plugins loaded before the
root conftest or ordinary child processes; the kernel-isolated full-suite runner
owns those boundaries. This qualifies the repository's local deterministic mock
tests, not live providers, deployment or adversarial code with Docker-daemon
administration privileges. Optional PostgreSQL tests remain separately opt-in;
no PostgreSQL execution is inferred from their default skips.
Browser evidence qualifies the declared IP-datagram-disabled profile, not stock
Chromium networking. It does not cover UDP, QUIC, WebRTC or ordinary DNS traffic;
all application origins remain explicit numeric loopback addresses.
Native-only qualification does not establish foreign-ABI coverage or the complete
source/configuration of the running kernel. Live BTF proves the selected hook
layout. Destination/header observations read userspace at hook time, not an
atomic copy of the kernel's later read; concurrent malicious mutation is not a
new universal guarantee. Connected-send classification relies on the declared
inherited-descriptor, io_uring and destination-attempt boundaries. Native QEMU
qualification is not guest-ABI semantic coverage or a claim about unexecuted
guest vector entries; its explicit boundary remains actual native kernel calls.

CI remains disabled at the user's request. These are local reproducible gates,
not a claim that GitHub Actions ran. Do not re-enable CI as an implementation
step. Do not change the evidence/history policy or another requirement's matrix
row under AC-15.
