# ORCH-07 verification note

Incoming work now has one atomic application receipt: the existing keyed WorkItem admission and primary Run receipt execute inside the same unit of work, and the service commits only after their created-or-replayed dispositions, Work-to-Run correlation, created catalog snapshot, and persisted sequence-one transition agree. A caller-owned `receive_in_uow` seam permits later audit composition without an inner commit. Faults before Run insertion, after the Run and transition flush, and after the service returns all roll back the newly admitted pair.

The validator marker retains its validator-issued in-process seal, catalog and schema hashes, and a canonical SHA-256 mutation fingerprint; this is an application integrity guard, not an authentication signature. The receipt service compares its catalog release with a constructor-captured composition snapshot before opening a transaction or allocating time and IDs; composition must rebuild this service when installing another catalog release. A fresh marker under that later catalog may replay an identical source event, but the original WorkItem, Run identity, catalog, configuration revision, and even terminal lifecycle state remain authoritative. An old marker is stale, and catalog drift never rewrites an admitted receipt.

External-action recovery now delegates its branch decision to a pure classifier over the persisted `ExternalAction` snapshot. The dispatcher still reconciles an exact durable connector receipt first. Without a call marker, any provider class may retry only while attempts remain; after a call marker, only required or supported provider idempotency may retry the same key within budget. Exhausted or unavailable post-call delivery becomes outcome-unknown rather than a blind write replay.

File-backed SQLite tests exercise independent-session identical and changed races, partial-pair faults, orphan and misdirection controls, terminal and catalog-release replay, and marker tampering. The full classifier truth table and RUN-05 recovery witnesses run under a socket-denied gate. Machine authority: `ORCH-07.json`. RUN-04, RUN-01, RUN-05, ingress transports, ORCH-09 audit append, and DEL-04 migrations retain their declared ownership.
