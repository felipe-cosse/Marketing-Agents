# AC-04 complete responsive hierarchy and Community deployments

Requirement: the UI presents the complete hierarchy, including 14 Community
instances backed by seven reusable templates.

Status: implemented and locally exercised. The final committed feature must
pass all declared gates and retain its tree-bound attestation before merge.

## Product changes

The graph and semantic tree now show the plan's complete Community summary:
`14 deployed instances · 7 reusable templates`. A shared pure presentation
function derives this wording from projected counts, including correct singular
labels for a filtered one-instance view. Community is selected by its stable
department ID, not by a coincidental pair of counts. No new React state, effect,
dependency, catalog data or API behavior is introduced.

Graph deployment chips now visibly say `Instance 1 of 2` or `Instance 2 of 2`.
Their existing accessible ordinal names remain intact. Department summaries can
wrap within the existing header instead of being ellipsized; the graph geometry
and typography are unchanged. Compact runtime labels retain their existing
ellipsis, title and complete accessible-description fallback.

## Acceptance journey

The two new cases in the existing WEB-07 browser file use the production Vite
build and real FastAPI catalog/detail routes. They do not fulfill or replace API
responses. The shared repository browser fixture enforces the exact same-origin
network boundary. The existing WEB-07 journey is preserved.

- Desktop Chromium, 1536x1024: load the graph, exercise zoom/fit, check the exact
  source-ordered hierarchy and every instance's parent/template/ordinal, then
  select all 14 Community cards independently and inspect each exact deployment
  and shared template ID. Closing the inspector restores focus to that card.
- Mobile Chromium, 426x923: fresh load defaults to the semantic tree alone;
  expand all 12 functions to expose all 61 tree items and 43 instances, then
  repeat all seven deployment pairs with exclusive selection and focus return.
- Both cases independently pin the seven canonical Community template IDs and
  all `.01`/`.02` deployment IDs, exclude the orchestrator from instance counts,
  check full visible ordinal text, reject clipped summary/chip geometry and
  horizontal page overflow, and assert no API mutations or hierarchy refetch.

The component cases use the existing generic hierarchy fixture to test all seven
pairs, complete ordering and selection callbacks. Separate filtered graph/tree
cases reject a stale fixed 14/7 summary. The real browser journey supplies the
canonical source-role and real HTTP detail evidence that this fixture cannot.

## Browser health and visual evidence

Identity, meaningful content, absent framework overlay, interactions, screenshot
evidence and browser health are asserted. The catalog-only API factory deliberately
does not compose operational runtime services. The only permitted HTTP failures
are GET 503 responses from these exact loopback URLs:

```text
http://127.0.0.1:4173/api/v1/approvals?status=pending&limit=100
http://127.0.0.1:4173/api/v1/agent-instances/status-summary
```

Each must have the expected sanitized `service_unavailable` Problem Details,
and every corresponding Chromium resource-error record must match one-for-one.
Unexpected warnings, page exceptions, errors, statuses, endpoints or multiplicities
fail the journey. This is not a claim that a catalog-only factory runs workflows.

Successful screenshots are retained in private external temporary directories
whose exact paths are printed by the browser runner. They cover the complete
desktop hierarchy, initial mobile tree, Community summary/pair and both first-pair
deployment/detail/template states. Local visual review confirmed complete Community
wording, distinct deployment headers, shared template identity and contained mobile
layout. Images and traces are not committed as application source.

production identity, Docker reverse-proxy or physical-device qualification.

screen-reader parity. CI remains disabled at user direction; no remote workflow
