# AC-13 — Public cancellation and honest in-flight recovery

Status: verified by executable local acceptance and focused regression checks;
exact committed-tree gates required before merge.

Requirement: `Queued cancellation cancels; executing is honest best effort.`

## Required behavior and implementation boundaries

Plans 03, 05 and 06 require immediate cancellation of queued work, an audited
request for executing work, suppression of future calls, preservation of bounded
in-flight authority, and honest recording of completed external effects. Plan 09
also explicitly requires `POST /api/v1/runs/{run_id}/cancel` with server-derived
operator authority. A terminal run remains immutable.

The new public route accepts only an empty JSON object. Both route dependencies
and the application command wrapper require an intact server-issued human
operator. The existing browser security boundary still enforces trusted origins,
hosts, Fetch Metadata, JSON content and the current CSRF token. The route bounds
request size, depth and execution time and delegates to the existing cancellation
coordinator rather than implementing another lifecycle. Actor and correlation
identity do not come from the request body or caller-supplied identity headers.

The response labels effect counts as cancellation-time snapshots. Preserved step
and action IDs can identify either in-flight or already-terminal work; they are
not a claim that work remains executable. `effects_reversed` is always false.
An unavailable response can follow a committed cancellation, so its fixed safe
message directs the caller to inspect the run and timeline before retrying.

The previous default worker selected only active runs. Consequently, cancellation
followed by worker interruption could leave an unfinished action or READ attempt
stranded under a terminal parent. AC-13 adds a separately classified, bounded
cancelled-run recovery lane. It must not add cancelled runs to ordinary workflow
execution or reach provider invocation, action retry/rearming, new budget
reservation, or another approval consumption.

Recovery uses the original persisted attempt/action identity and exact sealed
plan/control. WRITE recovery waits for both the action lease and bounded call
deadline. An exact durable receipt becomes succeeded; an absent receipt becomes
outcome unknown, with no provider replay. READ recovery closes an expired open
attempt and its executing step without creating an artifact or making another
call. Existing worker claim expiry/availability fences still apply. All outcomes
and their ordered audits commit atomically while the parent stays cancelled.
The default worker checks its current claim owner/token and unexpired lease in
each closure transaction, not only in a periodic heartbeat. A paused worker that
has lost ownership cannot close an attempt or append its outcome audit. WRITE
completion retains the original action lease for its compare-and-set authority
but attributes recovery audits to the actual recovery worker and correlation.

## Composed default-runtime acceptance

The composed acceptance cases use migrated and seeded SQLite, public admission,
approval and cancellation routes, the default runtime and real workers. They
cover queued and pre-barrier cancellation, success before cancellation, a genuine
mock receipt followed by a timely response, and interruption followed by restart.
Separate no-receipt and READ/model cases establish conservative bounded recovery.

Post-receipt interception awaits the original observed gateway before blocking
the response. It therefore does not manufacture provider success or receipt
authority. The no-receipt case blocks before the actual gateway call and never
releases it after cancellation. Public timeline and action details must agree
with durable state, original consumed approvals and immutable action identities.
The READ/model orphan case holds the genuine validated adapter result immediately
before the existing completion transaction. Interrupting inside the provider
instead would invoke the executor's intentional eager cancellation cleanup and
would not establish an orphaned-attempt restart case.
Before-deadline and repeated-restart checks must make no new calls or business
mutations. Focused tests supplement the journeys with authorization, malformed
transport, tampering, claim races and transactional boundaries.
Post-terminal idle checks advance beyond the worker's one-second availability
cooldown so that a held queue lease cannot substitute for proving no remaining
eligible work. Exact before-deadline probes retain their original clock boundary.

## Limits

The new journeys simulate interruption through task cancellation and reconstruct
the runtime in-process; they are not OS-kill or real-provider delivery tests.
Deterministic mock receipts prove local mock effects, not universal exactly-once
delivery. No compensation is implemented or implied. Cancellation-time counts
do not retroactively change when a previously in-flight result is reconciled.
Python test sockets are denied except local Unix sockets. CI remains disabled.
The default worker always supplies the transactional ownership fence. Standalone
application recovery methods also support internal low-level invocation without
a worker claim; their sealed aggregate/attempt fences still apply. The focused
tests use that boundary for negative controls, not as a replacement for the
default-worker journeys. No new live PostgreSQL concurrency result is claimed.
