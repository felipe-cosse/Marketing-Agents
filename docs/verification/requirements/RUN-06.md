# RUN-06 — Complete redacted runtime audit

RUN-06 completes the durable runtime record around the existing Run, Step, selection, approval, action, and receipt facts. Incoming work now carries a validator-issued, schema-derived redacted projection with its exact input schema ID and canonical content hash, highest retained classification, retention times, and keyed integrity digest. Exact replay returns the original projection and timestamps; projection tamper, schema drift, and secret-classified input fail before persistence.

Every controlled model or tool call persists one integrity-checked attempt containing its exact runtime identity, attempt number, reservation and deadline times, redacted input, input schema and classification, outcome, retry or terminal facts, allowlisted safe error, and successful artifact link. Personal or more restrictive attempt inputs are fully masked even when pointer metadata is incomplete. Provider payloads, raw exception detail, and secret or PII canaries are forbidden from attempt, completion, and artifact audit metadata.

Before reservation or provider invocation, controlled READ obtains one frozen output contract and checks its schema ID, canonical `schema-sha256-v1` content hash, classification, and provider kind against the sealed plan and operation. Returned structured output is validated against that exact Draft 2020-12 schema. Schema drift fails before a call; invalid output becomes the safe `output_schema_invalid` completion and creates no artifact.

A successful completion atomically stores an immutable artifact and its audit witness. The envelope binds payload and schema hashes to the exact Work, Run, plan, Step, selected instance and configuration, admitted-input digest, source classifications, provider version, and creation time. The repository permits exact replay, orders artifacts stably, rejects payload, provenance, schema-hash, and source-classification tamper, and validates optional parents as exact earlier same-Run ancestor outputs.

Attempt and artifact events use the same transactional, contiguous per-Run audit stream as existing intake, transition, planning and selection, approval, action, and receipt events. The focused gate also reruns those adjacent lifecycle, execution-control, idempotency, approval, typed-binding, and provenance suites under a declared no-network requirement. Machine authority: [`RUN-06.json`](RUN-06.json).

This evidence keeps several boundaries explicit. The validated minimized execution envelope is retained beside its redacted operator projection, consistent with plans 04 and 13; secret-classified material is not retainable. The catalog and planner seal schema content, while provider name, version, mode, and observation identity remain registered-adapter assertions. Controlled READ currently emits root artifacts with Work and external-observation sources; although the repository enforces supplied parent ancestry, dependency-output binding into execution remains a workflow-composition seam. Tests use deterministic adapters and file-backed SQLite, not live providers or distributed workers. PostgreSQL runtime behavior, Alembic rollout, public APIs, and the operator UI remain DEL-04, API-07, and WEB-06 scope.
