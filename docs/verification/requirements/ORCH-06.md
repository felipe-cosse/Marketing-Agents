# ORCH-06 — Bounded runtime controls

ORCH-06 seals retry, timeout, logical-call, payload, token, rate-limit, and cancellation policy into the immutable plan. Template and Run totals fail before execution authority, and the persisted execution-control projection independently rejects missing, inflated, drifted, or HMAC-tampered policy.

Generic READ execution commits an exact attempt, logical counter, and fixed-window slot before invoking an adapter outside the transaction. It uses both an absolute UTC deadline and a monotonic timeout, persists bounded retry eligibility only for classified transient failures, and recovers an expired crash-open attempt without double-counting. Total input, recursive normalized UTF-8 fields, output bytes, model-token usage, schema identity, binding revision, classification, redaction fields, provenance, and adapter identity are checked against the sealed contract.

WRITE delivery remains behind the exact released action and approval authority. One atomic call-start transaction claims the action, consumes the appropriate logical and rate capacity, records the durable call deadline, starts the WRITE step, and writes its audits before the gateway call. Provider-idempotent recovery waits for that deadline and reuses the same key; cancellation or a terminal sibling denial preserves a genuine in-flight call until receipt-first recovery can prove success or record an honest unknown outcome. Unstarted sibling actions and steps close in the same terminal unit of work.

Runtime denials use deterministic `runtime.control_denied` events with bounded codes, operation identity, and optional retry-after only. Payloads, measured sizes, provider exceptions, and worker identities are not retained in denial metadata. The storage suite checks atomic rollback, replay, races, malformed linkage, HMAC tamper, SQLite foreign-key integrity, and portable SQLite/PostgreSQL DDL.

The machine authority is [`ORCH-06.json`](ORCH-06.json). Its no-network gate runs the catalog, policy, controlled READ, execution-control, approval, WRITE-dispatch, audit, and adjacent regression suites. The connection witness restores the implementation paths to the base revision and requires that same gate to fail, proving the tests depend on the implementation rather than documentation alone.

The evidence does not claim external-provider atomicity, exactly-once effects, general compensation, a production worker loop, a live model provider, distributed or multi-region rate limiting, authenticated cancellation identity, Alembic migrations, or PostgreSQL runtime parity. Post-call cancellation cannot recall an effect. The dispatcher bounds the retained action result, while connector-owned durable receipt storage can retain a larger JSON-safe metadata record before reconciliation; adapter-level receipt quotas and retention remain later hardening. Full runtime JSON-Schema output validation, artifact persistence, and the complete operator attempt/output timeline remain SAFE-06, RUN-06, and AC-14 composition work.
