# AC-01 clean-checkout public startup

Requirement: a clean checkout starts with one command and no cloud credentials.

Status: verified by the successful isolated clean-checkout candidate run recorded
below. The traceability matrix reflects that observed acceptance result. Recording
the result changes the feature tree, so the final amended feature commit must still
pass all four manifest gates and produce its external tree-bound attestation before
merge.

## Acceptance boundary

The clean verifier materializes the selected commit into an isolated export. It
now reconciles the export's complete file inventory, Git blob identity and
executable modes with `git ls-tree` before building or starting anything. Caller
worktree files, ignored files, `.env` files and worktree-only edits therefore
cannot silently supply the startup source.
The same object reconciliation runs again after the entire journey; the separate
export fingerprint also frames paths, modes and contents unambiguously. Symlinks
and special files are rejected, and an ambient temporary root inside the caller
repository is refused.

The first runtime activation in that export is the documented public entry point:

```text
make -j1 up
```

It runs once from the exported source with only the verifier's scoped Compose
project, loopback port and selected source revision. No replay-fixture variables
are present. A nonzero public-startup result stops before runtime inspection or
fixture activation. Only after public readiness and inspection may the verifier
recreate the three fixture-consuming backend services with the explicit replay
overlay needed by the wider DEL-05 journey.

`scripts/ac_01_environment.py` makes the credential-free boundary an exact-map
contract rather than a list of suspicious names. It validates both expanded
Compose service environments and every live container environment. Live values
must be the exact merge of an immutable `sha256:` image baseline and the allowed
service overrides: local identity, mock model/connectors, external-network opt-out,
scoped SQLite/key/catalog paths, the API Unix socket where applicable, and
port-derived loopback origins. Web has no Compose environment overrides.

Image inspection also requires the pinned tracked base/runtime environment and
the container's exact image identity. Extra, malformed or duplicate variables,
ambient credentials, proxy/loader settings, or real-provider opt-ins all fail
closed. Errors contain fixed codes and service names, never rejected values.
The two public replay variables are permitted only for API, run-worker and
scheduler-worker after public readiness, and only when their scope equals the
owned Compose project.

## Evidence contract

The machine authority is `AC-01.json`. Its focused gate exercises the public
startup call path, failure ordering, direct-Compose bypass negative control,
exact environment helpers, browser-evidence retention, fresh-process catalog and
constraint import ordering, the separate-process replay fixture, and the existing
DEL-05 clean/Compose regressions. Those tests establish control behavior; mocks of
process and Docker inspection do not themselves prove a clean checkout starts
successfully.

The acceptance journey is therefore the fourth and final manifest gate:

```text
make verify-clean REF=HEAD
```

That gate exports the selected commit, uses fresh owned storage, invokes the
public startup command, observes the real loopback runtime and exact container
environments, completes the existing deterministic journey, runs offline
verification, and performs owned cleanup. Its network declaration is
`not_enforced`: acquisition can use registries, backend/test containers are
network-disabled, and the static web ingress retains its documented route.

The successful candidate record below binds the observed source and tree to a
private, sanitized clean report. The report records source identity, the public
command/result and boundary booleans/hashes, not host environment values or
payload secrets. Historical DEL-05/DEL-07 runs and OBJ-04 native-runtime evidence
remain useful regressions, but the final amended AC-01 feature tree must rerun all
four manifest gates for its external attestation.

Desktop and mobile PNG evidence from the owned browser container is retained in
a private temporary directory outside the repository. Only the two fixed image
names are copied from a validated container path. Failed copies and invalid
images remove that newly allocated directory; successful reports record image
paths and hashes. Containers and application volumes are still removed by the
existing scoped cleanup, while these public-demo images remain for review.

### Earlier failed candidate (2026-10-05)

Earlier candidate `69f6ab9cf0d16c34b7f4f4aef70c65978ce82a52` passed 189 focused
tooling/fixture tests and the real public startup in Docker Engine 29.8.2 / Compose
v5.5.1. The fresh deployed session reported local identity, mock model/connectors,
external network disabled, and exact 5/12/36/43 counts. Both public and replay
container environments matched the exact safe maps. The run then failed in the
separate replay-fixture process; owned cleanup passed with no remaining scoped
containers, volumes or network.

Redacted reproduction identified an import cycle: importing configuration
constraints first initialized the catalog package, whose eager seed export tried
to import the still-partial constraint module. The same cold import fails outside
Docker, while migration-first imports had hidden the problem in existing tests.
AC-01 breaks that load-time cycle without weakening the exact compiled-catalog
type checks and adds fresh-process import-order regression tests. This earlier
failure is not a completed clean-state acceptance record and is superseded by the
successful candidate above.

against the new final commit; no source or evidence file may change afterward.

## Limits

- Registry/base-image and frozen dependency acquisition are not offline by
  default; fully air-gapped acquisition requires prewarmed verified caches.
- Backend application and prebuilt test containers have no external network.
  The static web ingress container retains a disclosed outbound OS route, so this
  is not an all-container firewall claim.
- The journey qualifies local identity, SQLite, deterministic mock adapters and
  scoped Compose resources. It does not qualify real providers/delivery,
  production authentication, cloud deployment, TLS or production recovery
  objectives.
- Optional live PostgreSQL is outside AC-01. CI remains disabled at user
  direction, and no remote workflow or publication result is claimed.
