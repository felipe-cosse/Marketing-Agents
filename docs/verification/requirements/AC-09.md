# AC-09 — Reject reused, expired, or changed approvals

Status: verified by executable local public-API acceptance checks.

Requirement: `Reused, expired, or changed approval rejected.`
Plan 06 requires exact immutable action approval, finite decision validity,
one-time consumption, and unchanged-action expiry renewal with no early calls.

## New real-composition journeys

`tests/acceptance/test_ac_09_approval_rejection.py` uses a fresh migrated/seeded
SQLite installation, default runtime, real session/CSRF-aware ASGI endpoints,
real worker and production approval services/repositories. Observation wrappers
call the original deterministic model and connector methods. No product response,
repository, approval decision, reservation, receipt or provider result is stubbed.

### Reused approval

The first exact public approval succeeds while its sibling remains pending.
Repeating that decision returns a no-store `409 approval_decision_conflict`.
Bounded raw snapshots prove the decision and all selected durable authority,
effect and lifecycle-audit facts remain unchanged. Another real worker pass still
produces zero model, read-adapter or write-gateway calls, attempts or receipts.

Approving the valid sibling then completes the same workflow: exactly two write
calls, two first successful dispatch attempts, two durable receipts, one model
call and one unsent onboarding summary. Each observed proof joins to its exact
action, hash, request, decision, use, reservation and idempotency key. After runtime
close/reconstruction, both consumed decisions are rejected without changing those
facts or producing another call, attempt, receipt or artifact.

### Expiry and legitimate renewal

Controlled time reaches `now == expires_at` after only one approval. The pending
sibling decision and generation-zero reuse both fail without authority mutation
or calls. A real worker materializes both expirations, preserving immutable action
envelopes and emitting exactly two linked expiry audit events. No approval use,
reservation or effect exists. The expired state survives runtime reconstruction.

The current public error ordering is asserted explicitly:

| Attempt | State | Error |
|---|---|---|
| Decide pending leaf | Exact expiry, before worker expiry transition | `approval_expired` |
| Generation-zero reuse | Approved leaf at expiry, before transition | `approval_expired` |
| Generation-zero reuse | Persisted expired leaf | `approval_request_conflict` |
| Decide old leaf | Expired and renewed | `approval_decision_conflict` |

Each expired action renews through the real public route using its positive old
generation. There is exactly one new pending leaf with generation plus one,
pristine decision/use fields, an authoritative resource URL, and a linked expired
predecessor. Action/hash/authorization-set/plan/revision/step identity is unchanged.
Repeating the renewal returns the identical resource and creates nothing.

There remain two immutable actions and one set epoch, with four historical/current
approval requests. One fresh approval still yields zero calls; both fresh approvals
complete through the same real workflow, with the exact proof/receipt joins above.
Old approvals never regain authority. The actions remain unchanged after completion.

### Changed approved action

Three isolated cases change destination, minimized payload, or binding in an
already approved action's persisted canonical envelope while retaining its old
hashes and decision. This is private temporary-database fault injection, not a
supported public action-edit or replan feature.

The sibling's public approval fails with sanitized no-store `409 approval_conflict`
without reflecting a canary from the corrupted field. Domain hydration rejects
corruption, so bounded raw snapshots prove that the failed request changes no
authority or effect facts: the set stays open without release, there is still one
decision and the original approved/pending pair, and there are no uses,
reservations, attempts, receipts, artifacts or provider calls. Corrupted storage
is not repaired to manufacture a positive control; the independent genuine reuse
and renewal journeys above demonstrate valid completion.

Snapshots include run, steps, actions, requests, decisions, uses, set/head/member
rows, execution/dispatch attempts, receipts, artifacts and selected approval/action/
receipt lifecycle audits. They intentionally exclude session and worker-claim
bookkeeping; they do not claim the entire database is unchanged.

## Limits

Runtime reconstruction is in-process against durable SQLite, not an OS-process
crash. ASGI transport is local and all pytest gates deny sockets except local Unix
sockets. Connector effects remain deterministic mocks; no real email is sent and
no real-provider or universal exactly-once guarantee is claimed. New public
changed-action cases cover exactly destination, payload and binding; broader
field/policy permutations are supplementary regression evidence. CI is unchanged
and remains disabled.
