# SCHED-04 — Explicit skip and run-once misfire policies

SCHED-04 makes misfire handling an explicit schedule contract from catalog authoring through persistence. Every catalog `ScheduleBinding` and persisted `Schedule` carries a supported `skip` or `run_once` policy and an integer grace interval from zero through one day. JSON Schema, strict boundary validation, the schedule consistency digest, exact-create replay, and portable database checks cover those values; file-backed SQLite restart tests preserve both, while missing, fractional, out-of-range, and unrecomputed drift fail closed.

The misfire planner is pure and deterministic. It accepts only one exact persisted `Schedule` and its exact `ScheduleClaim`, verifies schedule ID, persisted due instant, recurrence version, and fencing version, and classifies solely at `claim.claimed_at_utc`. Equality with due plus grace remains on time. A strictly later claim is a misfire, so later worker processing time cannot change the decision.

For a misfire, the planner starts at the original persisted due instant and walks the existing wall-clock recurrence contract through every candidate at or before claim time. It returns one immutable plan containing the first missed instant, last coalesced instant, exact missed count, and first recurrence strictly after claim time. `skip` marks that single plan as no-work intent; `run_once` marks it as exactly one catch-up intent anchored to the original due instant. The scan has a hard 10,000-occurrence ceiling and fails closed without truncating the range. DST tests retain the established spring-gap and fold-zero behavior.

This requirement does not yet mutate occurrence, WorkItem, Run, audit, or schedule-next-time rows. SCHED-05 will consume this plan behind a live claim fence and atomically persist the selected outcome, next occurrence, audit, and lease release; SCHED-06 owns expired-lease recovery races. Runtime persistence is proven with file-backed SQLite, while PostgreSQL DDL is compiled but not run. Polling, metrics, APIs, authorization, migrations, deployment, and exactly-once execution remain outside this evidence. Machine authority: [`SCHED-04.json`](SCHED-04.json).
